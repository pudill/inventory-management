Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talks to a Python FastAPI service, which serves in-memory data loaded from JSON files at startup. There is no database and no persistence layer.

Request data flow — a filter change

  1. User picks a filter in FilterBarTime Period, Warehouse, Category, or Order Status. Values live in module-level refs inside useFilters, so every view shares the same state.
  2. View watches the filters and refetchesgetCurrentFilters() maps the UI state to { warehouse, category, status, month }.
  3. api.js builds the requestAny value equal to "all" is omitted; the rest become query params, e.g. GET /api/orders?warehouse=Tokyo&month=Q2-2025.
  4. FastAPI filters in memoryapply_filters() matches warehouse exactly and category / status case-insensitively. filter_by_month() expands Q1-2025…Q4-2025 to month prefixes and substring-matches order_date.
  5. Pydantic validates the responseList endpoints declare response_model (InventoryItem, Order, DemandForecast, BacklogItem); summary, spending and report endpoints return plain dicts.
  6. Vue stores raw data, derives the restResponses land in refs such as allOrders / inventoryItems; KPIs, chart series and tables are computed properties, formatted via currency.js and the active locale.

Observations

  • State is read-only: there are no write endpoints, so task and purchase-order actions in the UI will fail against this backend.
  • Backlog.vue exists but is not registered in the router; backlog data surfaces through the Dashboard and its modals.
  • Quarter mapping is hard-coded to 2025 in two places in main.py.
  • The user profile is mocked client-side in useAuth; there is no authentication.
  • CORS allows all origins, which is fine for a local demo only.
